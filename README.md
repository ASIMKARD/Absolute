# Absolute Universe — Reading Order

The reading-order tracker for DC's Absolute Universe (2024–2026), live at
https://asimkard.github.io/Absolute/. Offline web app only, no workbook.

**v8** was the first build on the Pull List template v3 (ASIMKARD/Pull-List-template).
It replaced v7 in place on `main` (John, 8 Oct 2026). v7 is tagged `v7-final`;
that tag is the one-step rollback. **v9** keeps reviews per issue again, as v7 did,
and brings back v7's five touches: big era numbers, row numbers, `[ ] [/] [X] [-]`
marks, `//` arc prefixes and full-width era bars.

- **Rules for every session:** `CLAUDE.md`. **Where the work stands:** `PROGRESS.md`.
- **Conventions** (versions, skins, the signature skin, the gate): `BUILD-NOTES.md`.
- **How v7 became v8** without losing anyone's progress: `MIGRATING.md`.
- Claude sessions load the `comic-tracker-build` Skill from `.claude/skills/comic-tracker-build/SKILL.md`.

## The loop

```
python3 tools/build.py          # dataset.json → data.js, sw.js, manifest.json
python3 tools/verify_gate.py    # the pinned verify.py + the order the app shows
node test/run.js                # jsdom harness — report the assertion count
npm run test:layout             # real Chromium — report the count
python3 tools/build.py --check  # generated files fresh
```

`npm ci` first if `node_modules/` is missing. Edit only `dataset.json` and
`signature.css`; never hand-edit what the build writes. CI
(`.github/workflows/harness.yml`) runs all of it on every push and pull request.

## What's where

| Path | What it is |
|---|---|
| `dataset.json` | the master: 134 rows, 2 eras, 24 monthly arcs, every date cited to the DC Database |
| `signature.css` | the Absolute skin: v7's black-and-red "absolute" look, and its five touches as decorations (`::before`/`::after`); its tokens are in `dataset.json` |
| `data.js`, `sw.js`, `manifest.json` | generated by `tools/build.py` — never hand-edit |
| `index.html`, `app.js`, `styles.css`, `qrcode.js`, `fonts/`, `icons/` | the app shell (the template's) and Absolute's own icons |
| `tools/` | build, verify gate (the pinned `tools/verify.py`), service-worker template |
| `schema/`, `test/` | the template's schema and both test suites; `test/layout/45-root.test.js` measures this data in every skin |

## Saved progress

Progress lives under `absolute:v3:`. On a first visit the app reads v7's keys
(`absolute:v1:`) once and copies marks, bookmarks, reviews (per issue, exactly)
and the skin choice across; the old keys are never written. Old `ABSO1:` QR codes
still import. Every row keeps v7's sort key as its `id`, so nothing is orphaned.

Reviews are per issue, under `absolute:v3:issue-reviews`. v8 kept them per month
(`absolute:v3:reviews`). v9 reads that store once, never writes it, and upgrades it
as John decided (8 Oct):
- a month's review that v8's migration made and nobody touched becomes v7's
  originals again, exactly;
- one written or edited in v8 is kept, on the month's first issue;
- one deleted in v8 stays deleted.

## Deploys

GitHub Pages serves `main` from the root (`.nojekyll`: files as they are).
After a merge, wait about 100 s, check the version in the header, and verify
every file by hash against the live site, never by HTTP 200.
